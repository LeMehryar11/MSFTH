GitHub Enterprise ROI challenge

Contoso: GitHub Enterprise investment case

A financially reasoned recommendation on migrating from Azure DevOps

Prepared for David Schankwirt and Johannes Starkwind · GitHub Copilot excluded from all figures

1 · Introduction

Contoso is weighing a move from Azure DevOps

  • Today: Azure DevOps Boards, Git and Pipelines; Nexus hosts artefacts separately.
  • Estate: approximately 3,000 private repositories and 500–1,000 users.
  • Existing security: BlackDuck, SonarQube and an in-house Dependabot equivalent.
  • Question: can GitHub Enterprise create enough value to justify migration and higher subscription cost?
Our case separates known licence costs from execution assumptions that must be measured.

3 · Pilot logic

Use measurement to narrow the financial range

  • Migration: record real hours per repository instead of relying on benchmarks.
  • Productivity: compare developer time before and after the move.
  • Tooling: verify coverage and actual savings before retiring anything.
The three measurements determine whether Contoso is in the conservative, base or upside case.
4 · Pilot scope and cost

A bounded test, not a full commitment

MetricRecommended pilotFull migration (for comparison)

Months 0–3: migrate 100 users and 300 repositories.

Months 3–6: measure effort, adoption and time saved; keep existing security tools.

Month 6: re-run the model with actual figures.

5 · Conclusion

Approve the pilot, then decide with evidence

Recommendation: approve the six-month, bounded pilot.
  • GitHub Enterprise only; no Advanced Security.
  • Do not approve the full migration on untested assumptions.
  • Use the month-six evidence gate to decide whether to scale and whether any tools can be retired.
