GitHub Enterprise ROI challenge

Contoso: GitHub Enterprise investment case

A financially reasoned recommendation on migrating from Azure DevOps

Prepared for David Schankwirt and Johannes Starkwind · GitHub Copilot excluded from all figures

1 · Recommendation

Adopt GitHub Enterprise; treat Advanced Security as an evidence-gated add-on

Migrate Git, Boards and Pipelines from Azure DevOps to GitHub Enterprise to consolidate the engineering platform. Do not roll out GitHub Advanced Security across all active committers at this stage.

Contoso already runs BlackDuck, SonarQube and an in-house Dependabot equivalent that meet today's needs. Paying for GitHub Advanced Security across 60% of users on top of that is not currently justified by the numbers — see the financial case on the next slide.

Instead: pilot Advanced Security on a small, named set of the highest-risk repositories, measure the value it adds beyond the existing tools, and only then decide on wider rollout.

3 · Cost response

"This subscription is too expensive"

Yes — on licence cost alone, that is correct. GitHub Enterprise ($21/user/month) plus Advanced Security ($49/user/month) is structurally more expensive per seat than Azure DevOps ($6/user/month), at every discount tier on offer. No realistic scenario recovers that gap through licence cost alone.

That is exactly why we are not recommending a blanket like-for-like swap. The recommendation is to pay for the consolidation value GitHub Enterprise genuinely adds, and to treat Advanced Security as optional spend, gated on evidence, rather than a default line item.

This keeps incremental spend proportionate to demonstrated value, rather than committing to the full cost on assumptions alone.
4 · Scope, effort and timeline

A phased path to a evidence-based decision

  1. Months 0–3 — Pilot. Migrate Git, Boards and Pipelines for a defined pilot group on GitHub Enterprise. Confirm the real user count and negotiated discount tier. No Advanced Security rollout in this phase.
  2. Months 3–9 — Platform migration. Migrate the remaining approximately 3,000 private repositories via the preferred partner (≈€240/hour/person). Track actual effort against the 0.5–2.0 hour/repository planning range used in this model.
  3. Months 9–15 — Security pilot. Trial Advanced Security on a small, named set of the highest-risk repositories only. Measure realised value against the BlackDuck/SonarQube baseline.
  4. Month 15 — Review. Re-run this financial model with real data before committing to Advanced Security at scale.
5 · Evidence to collect before committing budget

Six inputs that materially change the numbers

  • A firm user-count commitment — 500 versus 1,000 users roughly doubles total spend.
  • The discount tiers Microsoft actually agrees for GitHub Enterprise and Advanced Security.
  • Contoso's current BlackDuck, SonarQube and Nexus licence spend, to value any tool retirement.
  • A confirmed EUR/USD basis, since licence pricing is quoted in dollars and the partner's migration rate in euros.
  • A real migration-effort estimate per repository from the preferred partner, replacing the planning range used here.
  • Whether Contoso will also take Microsoft's Unified Support, and its cost.
6 · Decision requested

What we are asking the executive team to approve today

  • Approve a bounded Phase 1 pilot: GitHub Enterprise only, no Advanced Security, for a defined pilot group.
  • Defer any Advanced Security commitment until the Phase 3 pilot produces evidence.
  • Nominate an owner to collect the six evidence items above within 30 days, so the model can be re-run with real figures.
This is a recommendation to proceed carefully and cheaply toward a better-informed decision — not a recommendation to commit to the full programme today.
