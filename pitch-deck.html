Contoso: GitHub Enterprise investment case

A financially reasoned recommendation on migrating from Azure DevOps

Prepared for David Schankwirt and Johannes Starkwind · GitHub Copilot excluded from all figures

1 · Recommendation

Run a bounded pilot to find out which scenario Contoso is actually in

With discount now fixed at the handout's maximum in every scenario (per Contoso's confirmation), the financial case no longer hinges on negotiation — it hinges entirely on execution: how efficiently the migration itself is run, how much developer time is genuinely saved, and whether Contoso actually retires BlackDuck, SonarQube and Nexus. Those three factors alone span a payback range from never (conservative) to about 17 months (upside) at 500 users.

That is too wide a range to commit the full ~3,000-repository budget against. We recommend a small, bounded pilot — roughly 100 users and 300 repositories (10% of the estate), GitHub Enterprise only, no Advanced Security — specifically to measure real migration effort and real developer time saved, before deciding at what scope to proceed.

Advanced Security is not recommended at any scale yet. Contoso's existing BlackDuck, SonarQube and in-house Dependabot equivalent already cover this need, and GitHub has a track record of porting Advanced-Security-equivalent capability back into Azure DevOps within roughly 6 months of release (see Slide 4) — a further reason not to retire proven tools in a hurry.

3 · Cost response

"This subscription is too expensive"

It depends entirely on execution, not on negotiation. GitHub Enterprise plus Advanced Security costs materially more per seat than Azure DevOps even at the maximum available discount — that part is fixed. What is not fixed is how efficiently the migration is executed, how much developer time is genuinely saved, and whether existing tools are actually retired. Get those right and the upside scenario pays back in under a year and a half; get them wrong (as in the conservative scenario) and it never pays back.

That is exactly why we are not recommending a full commitment today. We are recommending a small, bounded pilot (, see Slide 5) — a fraction of the a full migration would cost under these same assumptions.

The pilot's whole purpose is to find out, cheaply, which of these scenarios Contoso is really facing — before betting the full migration budget on an assumption.

6 · Evidence to collect before committing further budget

What still needs to be confirmed

  • A firm user-count commitment — 500 versus 1,000 users still roughly doubles total spend, even with discount now fixed.
  • A real migration-effort estimate per repository from the preferred partner, replacing the 2.5–10 hour/repository planning range used here.
  • Contoso's current BlackDuck, SonarQube and Nexus licence spend, to replace the researched placeholder figures on Slide 4 with real ones.
  • Whether GitHub's Advanced-Security-equivalent features really do reach Azure DevOps within about 6 months — this materially affects whether retiring existing tools is wise.
  • A confirmed EUR/USD basis, since licence pricing is quoted in dollars and the partner's migration rate in euros.
  • Whether Contoso will also take Microsoft's Unified Support, and its cost.
7 · Decision requested

What we are asking the executive team to approve today

  • Approve the bounded pilot only (, Slide 5) — GitHub Enterprise, no Advanced Security, for a defined pilot group.
  • Do not approve a full-scope migration or Advanced Security rollout today — the range between scenarios is too wide to commit against untested assumptions.
  • Nominate an owner to collect the evidence on Slide 6 during the pilot, so the model can be re-run with real figures at the month-6 decision gate.
This is a recommendation to spend a small, bounded amount to find out which scenario is real — not a recommendation to commit to the full programme today.
